# Проверка качества MCP security: 10 октября 2026

## Исправления 0.13 / observer 3 / themis-mcp/2

Это исторический аудит редакции 0.12; таблица ниже сохраняет исходные находки. В текущем коде исправлены неполные наблюдения, запуск lifecycle без entry point, canary defaults/required, подсчёт ошибок вызова, смешивание DNS источников, 503→false provenance, чтение `.env`, проверка подписи/свежести/связности THEMIS, пропуск call-network и обход середины больших результатов. Возможности инструментов больше не объявляются безопасными по отсутствию английских слов; нужны привязанные операторские capabilities. HISTOR использует vendored WARDEN 0.13.

Добавлены HTTP/HTTPS/SMTP-ловушки и регрессии скрытой копии письма, обязательный host firewall с проверкой состояния, подписанные события package/definitions, cursor API/Atom, webhook worker с HMAC, сохранением позиции и повторами, census manifest, генератор 72 поведенческих fixtures MOMUS и ежемесячные шаблоны запуска. [Текущие условия эксплуатации и ограничения](../../histor/docs/behaviour-v3.md). [Повторные безопасные воспроизведения](mcp-quality-reproductions-v13.json).

Проверки текущей редакции: WARDEN 426; MOMUS 498 (1 skip); HISTOR 308 в полном прогоне (134 skip, включая PostgreSQL без DSN), плюс адресная регрессия PyPI dependency constraints; THEMIS 182, coverage 98,57%. HTTP/HTTPS/SMTP fixtures и синтаксис всех 72 программ проверены локально.

Полный semantic+static замер: **8 244/8 244 атак**, **0/362 ложных блоков**, **0 incomplete**; [проверяемый отчёт](coverage-v13.json). Испанский false positive устранён общим критерием authority violation.

Что этим изменением не подтверждается: реальный gVisor acceptance и обход всего каталога; активация production-таймеров/webhook; криптографическая верификация registry attestations (пока явно unknown, а не «verified»); проверка всех языков и всех ветвей поведения. Локальный Docker daemon недоступен. Неподдерживаемые протоколы/trace records и относительные пути оставляют наблюдение incomplete; они больше не приводят к approve. Новые production-правила из MOMUS автоматически не публикуются.

Реализация содержит большую часть заявленных компонентов, но полный сценарий «проверили пакет и можно ставить» пока не подтверждён. Главные пробелы — полнота наблюдения в песочнице, недостаточные основания для `approve` и обход проверки длинных результатов. Метрики распознавания описаний WARDEN измеряются отдельно от поведения кода и успешности эксплуатации.

Проверены текущие исходники HISTOR, WARDEN, THEMIS, MOMUS, тесты и публичная статистика HISTOR. Чужие пакеты и инструменты живых серверов при аудите не запускались. Production не менялся. Статус ниже относится к коду в рабочем дереве; наличие кода не доказывает включение функции на сервере.

## Что исправлено в WARDEN 0.12.0

На прежнем корпусе 8 606 примеров в 11 языках, с DeepSeek и `--classifier-blocks` при пороге `high`: **0 пропусков из 8 244 атак вместо 16; 1 ложная блокировка из 362 контролей (0,28%) вместо 32 (8,84%); 0 неполных проверок**. Все прежние 16 пропусков и 32 ложные блокировки исправлены. Осталась новая ошибка модели на закодированном испанском описании обычной задачи. [Полный отчёт](coverage-v12.json).

Подтверждённая смысловая атака больше не может получить пропускающий её `low/medium`. Исключения для неоднозначного base64 и цитат в JSON разрешаются только полным чистым смысловым вердиктом, связанным со всем проверенным снимком инструмента. Остальные проверки остаются. Офлайн-результат не ослаблен: 2 808/8 244 атак блокируются, 31/362 ложных блокировок; улучшенные числа выше требуют включённого смыслового слоя. Это синтетический набор, использованный при доработке, а не доказательство защиты на любом языке.

Дополнительные ограничения песочницы: lifecycle exit code/timeout не сохраняются в результате фазы;  `read_trace` разбирает только `execve`, `connect`, `open/openat`, хотя runtime записывает больше syscall; относительные пути приманок не разрешаются через cwd/dirfd; попытка открытия не отделена от успешного чтения. При неизвестном IP DNS-выборка захватывает все контейнеры. Ограничение обращений контейнера к host gateway в [install.sh](../../histor/sandbox/install.sh#L57) устанавливается условно через UFW и не проверяет его активность: конфигурацию изоляции нужно подтверждать сетевым acceptance-тестом. Живую конфигурацию sandbox host этот аудит не проверял.

README HISTOR уже различает remote endpoints и запуск registry packages, но обещание «никакой инструмент не вызывается» осталось в [packages.py](../../histor/histor/packages.py#L5) и некоторых текстах landing. README говорит «each tool», хотя лимит равен 15. Перед публикацией заявления надо привести к фактическому покрытию.

## Проверки и границы вывода

- WARDEN: 422 теста прошли на редакции 0.12.0, включая негативные проверки semantic clearance, изменения input во время запроса, forged review, advisory/uncertain и CLI lock update.
- MOMUS: 496 тестов прошли, один пропущен; есть адресные проверки resume, identity, отсутствия ключа в отчётах и суммирования production-вердиктов.
- THEMIS: 162 теста прошли, покрытие 98,04%. Текущие тесты закрепляют и слабую семантику `approve`, поэтому зелёный suite не опровергает дефекты выше.
- HISTOR: 81 выбранный package/lookalike/API/crawler тест прошёл на SQLite; 70 PostgreSQL-варианты пропущены, поскольку тестовый DSN не задан. Полноценный gVisor behavior acceptance не запускался.
- Все воспроизведения — без сети, кроме отдельных публичных GET статистики. Изменения безопасности в этой редакции ограничены WARDEN и его MOMUS-замером; перечисленные дефекты HISTOR/THEMIS не объявляются исправленными.

Рекомендуемая последовательность исправлений: полнота evidence и запрет необоснованного `approve`; закрытие обхода длинных результатов; независимая lifecycle-фаза и протокольные сетевые ловушки; затем обязательные sandbox acceptance fixtures и подключение их к MOMUS. После этого имеет смысл считать поведенческое покрытие всего каталога. Утверждение «никто в мире такого не делает» этим код-аудитом не проверялось.
